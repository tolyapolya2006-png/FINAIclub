# FU AI Club — AGENTS.md

Постоянные инструкции для Codex в этом репозитории.

## Контекст

Это официальный **по названию проекта** сайт студенческого сообщества FU AI Club, посвящённого практическому применению AI среди студентов Финансового университета. **Не утверждать**, что клуб уже получил официальный статус от университета: исходный документ описывает его получение как план. Основные мероприятия предполагаются бесплатными и доступными студентам; не изобретать коммерческих тарифов, достижений или партнёров.

## Авторитет документов

1. `CONTENT.md`: одобренные пользовательские тексты — не переписывать без запроса.
2. `SITE_STRUCTURE.md`: информационная архитектура, маршруты, поведение и регистрации.
3. `DESIGN.md`: дизайн-система и визуальная приёмка.
4. `references/01-original-visual-direction.png`: первичный визуальный эталон; последующие макеты — детализация.
5. Другие файлы references — вспомогательные; изображения не являются достоверным источником дат и событий.

При расхождении сообщить о конфликте, не разрешать его произвольной переработкой дизайна/контента.

## Принципы выполнения

- Работать итерациями. Сначала проверить репозиторий и доступные файлы, затем предложить краткий план, потом реализовать **один контролируемый этап**. Не переписывать весь сайт при исправлении одного компонента.
- Не делать новый дизайн вместо согласованного Premium Minimalism.
- Mobile-first: проверять 320 / 390 / 768 / 1440 px. Приоритет читаемости, скорости загрузки и взаимодействий с телефона.
- Беречь стеклянную серебристо-лавандовую ленту: основная композиция hero + небольшие фрагменты в отдельных нижних секциях, без перегруза и без generic glow blobs.
- Не использовать целый PNG-макет как скриншот вместо интерфейса. Заголовки, кнопки, карточки, фильтры и навигация — настоящие HTML/React элементы.
- Не выдумывать мероприятия, даты, имена, числа участников, партнёров, email и ссылки. Показывать пустые/безопасные состояния.
- Не добавлять сложный backend, регистрацию пользователей, CRM или CMS без явного согласования. MVP событий — типизированный локальный data-файл с внешними формами регистрации.
- Не менять сохранённые данные, деплой, домен или доступы без запроса; секреты не коммитить.
- При необходимости создавать дополнительные файлы документации кратко, без дублирования противоречивых правил.

## Технический процесс

1. Проверить стек: если пустой репозиторий — предложить Next.js + TypeScript + Tailwind CSS; не менять существующий стек без причины.
2. Проверить `references/` и реальные графические ассеты. Если отсутствует пригодная версия ленты с прозрачностью, прямо сообщить; не подменять случайной фигурой.
3. Реализовать сначала компоненты, header и главную; затем `/events` и пустое состояние; затем мобильное меню и полный responsive QA.
4. После каждой визуальной итерации выполнить сборку/проверки и **открыть сайт в настоящем браузере** (Playwright или доступный эквивалент). Сделать desktop/mobile скриншоты, сравнить с макетами.
5. Исправлять сначала композицию, потом шрифты, графику, сетку, адаптивность и детали. Повторять проверку.
6. Если браузер/skill недоступен — сообщить, какой этап не проверен. Не утверждать, что дизайн проверен, только потому что `npm run build` успешен.
7. В конце задачи дать понятный отчёт по изменённым файлам, проверкам, скриншотам, ограничениям и следующему шагу.

## Стандарты качества

- Accessibility: alt/aria, фокус, контраст, семантические заголовки, reduced-motion.
- Performance: оптимизированные изображения, без бессмысленного тяжёлого 3D, контроль layout shift.
- Не добавлять generic AI design: бессмысленные градиенты, одинаковые SaaS-секции, карточки с несуществующими метриками, стоковые портреты, излишние тени, случайные emoji.
- Обновлять документацию, когда пользователь утверждает изменение дизайна/содержания; не исправлять утверждённые решения молча.

## Первая задача после загрузки пакета

Прочитать 4 документа и папку `references/`, проверить реальное состояние репозитория, сообщить о недостающих файлах/ассетах и предложить пошаговый план. **Не начинать реализацию целого сайта до отдельного задания владельца.**
