# FU AI Club — SITE_STRUCTURE.md

Версия: 1.0 · 19 ноября 2026
Статус: согласованная IA/UX-спецификация v1, без неподтверждённых дат, ссылок и партнёров.

## 1. Цели сайта

- За 5–10 секунд объяснить посетителю, что такое FU AI Club и зачем присоединяться.
- Показать смысл клуба, форматы и свободное участие без обязательного членства.
- Дать быстрый путь к Telegram-каналу/чату и отдельный путь к мероприятиям.
- Обеспечить понятный переход к форме регистрации **каждого реального** мероприятия.
- Дать канал для предложения сотрудничества.

Фокус посещений — **мобильные устройства**; desktop полноценный, не вторичный.

## 2. Карта страниц

```text
/                    Главная
  #about             О клубе
  #activities         Что мы делаем / Направления
  #community          Сообщество
  #partners           Партнёрство
/events              Мероприятия
  фильтры категорий  внутри /events, без обязательных отдельных URL
```

В версии 1 отдельная детальная страница события и встроенный backend регистрации **не обязательны**: внешняя форма привязана к событию. Архитектура должна позволить их добавить позднее.

## 3. Глобальная шапка

- Бренд FU AI Club → `/`.
- «О клубе» → `/#about`; «Направления» → `/#activities`; «Мероприятия» → `/events`; «Сообщество» → `/#community`; «Партнёрство» → `/#partners`.
- CTA «Присоединиться» → живой Telegram-канал/чат по решению владельца. Пока URL неизвестен — безопасное неактивное/непубликуемое состояние, **не** `href="#"`.
- На mobile — компактный logo и настоящая кнопка меню; после перехода закрывать меню.
- Подсветка текущего маршрута на `/events` деликатной лавандой.

## 4. Главная `/` — порядок и действия

| Порядок | Раздел | Содержание | Действие |
|---|---|---|---|
| 1 | Hero | Крупное FU AI / Club, слоган «Изучай и Практикуй.», подзаголовок и описание | «Присоединиться к сообществу» → Telegram; «Узнать о клубе» → `#about` |
| 2 | О клубе | Манифест и 4 абзаца + принципы | Чтение, anchor `#about` |
| 3 | Что мы делаем | 4 направления в карточках (одна тёмная) | Информировать; не выдумывать отдельные страницы направлений |
| 4 | Сообщество | Для разных уровней подготовки | Telegram-канал и чат, когда URL подтверждены |
| 5 | Партнёрство | Предложение экспертам и компаниям | Реальный email `mailto:` или контакт; без заглушки как активной ссылки |
| 6 | Footer | Контакт и короткая навигация | Ссылки на доступные маршруты |

**Мероприятия на главной:** отдельная страница `/events` присутствует в меню и footer. В v1 НЕ добавлять полный каталог на главную. Необязательный блок ближайшего **реального** события — только после появления настоящих данных и отдельного согласования дизайна.

## 5. Мероприятия `/events`

1. Hero «Мероприятия» + утверждённый текст «Место, где идеи становятся опытом.» и абзацы из CONTENT.md.
2. Если есть реальные опубликованные мероприятия: компактные фильтры «Все события», «Лекции», «Воркшопы», «Соревнования», «Встречи» (категории допускается менять согласно реальным данным); далее карточки.
3. Если мероприятий нет: вместо демонстрационных карточек показать утверждённый empty-state из CONTENT.md и CTA «Следить за анонсами» → реальный Telegram.
4. Внизу страницы допускается аккуратный CTA «Следи за анонсами в Telegram» с фрагментом ленты; без обещаний будущей даты и других выдуманных фактов.

### Структура одной карточки

- название мероприятия;
- тип/категория;
- краткое описание;
- дата и время **только если подтверждены**;
- формат (online/offline/hybrid) и место **только если подтверждены**;
- информация о регистрации (статус, URL);
- CTA согласно статусу.

### Состояния события

| Статус | Отображение | Кнопка |
|---|---|---|
| `announced` | Анонс есть, регистрация ещё не открыта | «Регистрация скоро» (disabled), либо ссылка на анонс при наличии |
| `registration_open` | Дата/место подтверждены, форма существует | «Зарегистрироваться» → валидный `registrationUrl` |
| `registration_closed` | Запись закрыта | «Регистрация закрыта» (disabled) |
| `completed` | Событие прошло | Без активной регистрации; по возможности ссылка на отчёт |

Не показывать кнопку «Зарегистрироваться» активной, если `registrationUrl` отсутствует. Для событий с датой в прошлом не оставлять статус `registration_open` без проверки. Фильтрация должна работать по данным.

### Хранение событий (предлагаемый технический вариант)

Для MVP — `src/data/events.ts` или `src/data/events.json`, без CMS и базы. Типизированная структура (пример полей, **не пример реального мероприятия**):

```ts
type Event = {
  id: string;
  title: string;
  category: 'lecture' | 'workshop' | 'competition' | 'meeting';
  description: string;
  startsAt?: string;       // ISO, с часовым поясом при необходимости
  format?: 'online' | 'offline' | 'hybrid';
  location?: string;
  status: 'announced' | 'registration_open' | 'registration_closed' | 'completed';
  registrationUrl?: string;
  recapUrl?: string;
};
```

Изначально коллекция `events` должна быть **пустой**, пока владелец не предоставит реальные данные. При добавлении события проверять URL и корректность даты/временной зоны.

### Формы регистрации

Форма создаётся отдельно (например, через Яндекс Формы), а в событии хранится её реальная HTTPS-ссылка. Кнопка открывает соответствующую форму; открытие в новой вкладке — с `rel="noopener noreferrer"`. Сайт v1 не собирает персональные данные регистрации и не обещает хранить их сам. При необходимости интеграции формы внутри сайта — отдельная задача с согласованием обработки данных.

## 6. Конфигурация контактов

Добавить один понятный файл конфигурации, например `src/config/links.ts`, с полями `telegramChannelUrl`, `telegramChatUrl`, `partnershipEmail` или `partnershipContactUrl`. Все значения первоначально `null`/пустые. Не использовать случайные адреса и каналы. До реальных URL прятать ссылку или честно показывать, что контакты уточняются, а не вести на несуществующую страницу.

## 7. UX/доступность

- Семантические `<main>`, `<section>`, `<nav>`, `<footer>`, `h1` на каждой странице.
- Рабочая клавиатурная навигация, фокус, aria-label для меню; контрастность текста.
- Учесть reduced motion; alt для содержательных изображений, `aria-hidden` для чистой декорации.
- Состояния загрузки, пустого каталога, отсутствующей ссылки, открытого мобильного меню.
- Нет внезапных pop-up и самопроизвольных перелистываний.

## 8. Приёмка MVP

- `/` и `/events` открываются прямой ссылкой и через меню.
- Кнопка «Узнать о клубе» прокручивает к нужному разделу.
- На мобильном меню работает, не мешает чтению, ссылки работают.
- Список событий пуст в исходной конфигурации; ни одно демо-событие не опубликовано как реальное.
- Добавление одного настоящего события в файл данных отображает нужную карточку, фильтр и CTA.
- Никаких 404, битых изображений, ложных контактов и горизонтального overflow на 320/390 px.
- Внешние формы открываются корректно только для события со статусом регистрации `registration_open`.
